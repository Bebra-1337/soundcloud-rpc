# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

A native desktop SoundCloud client in C++ / Qt 6 Quick: the user signs in with their own account and the app shows Home, Feed, Library, Search, playlist and artist pages in its own QML UI (no embedded website), plays audio with QtMultimedia, publishes Discord Rich Presence, exposes MPRIS over D-Bus, has a QML idle screen with 15 themes, and lives in the system tray. Linux-only, packaged via a Nix flake (`package.nix`, CMake). There is no test suite or linter.

## Commands

```bash
nix develop                                   # dev shell (inputsFrom the package + clang-tools, gdb); nix-shell uses shell.nix pinned to flake.lock
cmake -B build -G Ninja && cmake --build build
./build/soundcloud-rpc                        # add --minimized / -m to start in the tray; soundcloud.com URLs as arguments are opened
./build/soundcloud-rpc-preview                # gallery of idle themes with fake data
nix run                                       # build and run the packaged app
nix build                                     # produces ./result
```

New source or QML files must be added to `CMakeLists.txt` (main UI: the `ui_qml` list; idle themes: `qml/idle/CMakeLists.txt`) and `git add`ed before `nix build`, since flakes only see tracked files. Qt logs go to the journal when stderr is not a terminal; set `QT_FORCE_STDERR_LOGGING=1` to see them in a pipe. `main.cpp` adds `--log-level=3` to `QTWEBENGINE_CHROMIUM_FLAGS` (Chromium's ERROR spam about the website's third-party requests) unless the variable already sets a log level; FFmpeg's own log is lowered to errors unless `QT_FFMPEG_DEBUG` is set.

## Platforms

Linux is the only tested platform. Linux-only code is guarded with `Q_OS_LINUX` (and in CMake with `CMAKE_SYSTEM_NAME STREQUAL "Linux"`, which also keeps Qt6::DBus out of other builds): `ThemeWatcher` (qt6ct palette), `Mpris` (D-Bus), and in `DiscordIpc` the `XDG_RUNTIME_DIR` / Flatpak / Snap socket paths. On Windows `DiscordIpc` tries the `discord-ipc-N` named pipes; macOS uses `$TMPDIR`. Other platforms have not been built yet. Colors: `Style.qml` picks its source from `App.colorMode` (`auto` / `system` / `dark` / `light`, QSettings `ui/colorMode`, tray: *Appearance*, or the settings page). `system` is the Qt palette (qt6ct), `dark` / `light` are SoundCloud's media-kit colors (black `#121212`, white `#FAFAFA`, orange `#FF5500`, black text on orange), with the same mixes between them as before. `auto` is `system` where `App.systemPaletteDefault` is true (Linux with qt6ct), otherwise `dark`. The idle themes are not affected.

## Architecture

`src/main.cpp` creates `Application` (`src/app`), which builds the backend objects, registers them as QML singletons in the `ScBackend` import (`App`, `Api`, `Auth`, `Player`, `Analyser`, plus the `PagedListModel` type), loads `SoundCloudRpc/Main.qml`, and owns the tray and window lifecycle (closing hides to the tray via an event filter on the window; only `quit()` exits).

- **API** (`src/api/SoundCloudApi`): client for `api-v2.soundcloud.com`, the internal API the website runs on, signed in as the user (`Authorization: OAuth <token>`) with the web player's `client_id`. `ClientIdProvider` scrapes that id from soundcloud.com's JS bundles (`a-v2.sndcdn.com/assets/*.js`), caches it in QSettings (`api/clientId`) and fetches it again when a request gets 401/403 (rotated id; at most once a minute, one retry per request). A 401 that persists only signs the user out when `/me` itself fails (`verifyToken`), so one endpoint refusing can't log out. Every full track object in any response is cached (`harvest` / `rememberTrack`) for the player. Endpoints are undocumented and change without notice: when something stops loading, compare with the site's network log first. QML helpers take a JS callback `(result, error)`: `loadHome` (play history + `/mixed-selections`), `loadPlaylist` (completes the playlist's track stubs via `/tracks?ids=` in batches of 50), `loadUser`, `resolve`, `request`. Likes are a set of ids (`/me/track_likes/ids`, falling back to the first 200 likes) with optimistic `setLiked`; `likesRevision` is the property QML bindings depend on.
- **Items** (`src/api/Entities`): everything shown in lists is a flat map with `kind` (`track`, `playlist`, `system-playlist`, `station`, `user`), `id`, `urn`, `title`, `artist` (subtitle), `artwork` / `artworkLarge`, `permalinkUrl`, plus kind-specific fields (`durationMs`, `playable`, `snippet`, `repostedBy`, `trackCount`, `isAlbum`, `followers`, `userId`). `sc::item` unwraps collection entries (`{type, track, user}` stream items, `{track}` likes/history, `{playlist}` / `{system_playlist}` library entries). `pickTranscoding` chooses non-encrypted HLS (AAC preferred, then MP3/Opus) or progressive; tracks offered only as `cbc-/ctr-encrypted-hls` need Widevine and are marked unplayable (lock icon) and skipped; never try to work around DRM. A full non-encrypted stream always beats a `snipped` one; when only the 30-second snippet is playable (Go+ tracks on a free account, or a full version that exists only DRM-encrypted: `fullOnlyOnSite`) the item is `snippet` and gets a PREVIEW badge with a tooltip saying which. Wrapper entries can carry a `kind` of their own (`{"kind": "like", "track": {...}}`), so only a `kind` naming an entity (`isEntityKind`) means the object is the entity; items without id and urn (promo cards) are dropped.
- **Lists** (`src/models/PagedListModel`): QML-creatable model over one collection endpoint (`path`, `query`, `pageSize`), loads the first page once the API is ready and further pages through `next_href`; views call `loadMore()` near the end (`ItemList`, `ItemGrid`). `setItems()` makes it a static list (playlist tracks). Role `item` is the item map. `refresh()` reloads the first page but keeps the old rows until it arrives; `isStale(ms)`, `prepend()`, `removeById()` serve the Library: its sections reload when shown again after 2 min (likes from the phone or the site) or from the refresh button (also `Api.refreshLikedIds()`), and the Likes list follows `Api.likeChanged(track, liked)` (optimistic, reversed if the server refuses) without a reload.
- **Player** (`src/player/PlayerController`): `QMediaPlayer` (FFmpeg backend, plays the HLS m3u8) + `QAudioOutput`. Queue of item maps with a play order (`m_order`, shuffled with the current track first) and `m_pos`; every track start bumps `m_generation` so stale async callbacks are dropped. A track is resolved by fetching it if not cached, picking the transcoding, then `GET transcoding.url?track_authorization=...` → `{url}` (signed, short-lived). Stale `track_authorization` (401/403/404) refetches the track once; a playback error re-resolves once at the current position; after a pause longer than 10 min the stream is re-resolved on resume. End of queue without repeat appends `/tracks/{id}/related`. The first play of each track is reported to `/me/play-history`. The waveform comes from `waveform_url` (PNG URLs on wave.sndcdn.com are rewritten to the JSON on wis.sndcdn.com), downsampled to 120 bars. Volume/shuffle/repeat persist in QSettings (`player/*`). Start latency: `QPlaybackOptions::probeSize` is 64 KB (FFmpeg's default probing fetched several HLS segments before playing; the AAC init segment has all it needs), and once a track is audible the next one in the play order gets its stream URL resolved ahead (`prefetchNext`, used for up to 5 min), so a skip or the automatic next starts without API round trips.
- **Anti-bot fallback** (`src/api/WebSession`): DataDome sits in front of api-v2 and refuses some requests from a plain HTTP client with `403` + `x-datadome: protected` and a `captcha-delivery.com` URL in the body; likes (`PUT/DELETE /users/{me}/track_likes/{id}`) are refused this way, reads and `/me/play-history` are not. `SoundCloudApi::dispatch` sends such a request again through `WebSession` and from then on sends writes there directly (`m_writesViaWeb`): a hidden `QWebEnginePage` on https://soundcloud.com/ in the user's profile runs it with the page's own `fetch()` (MainWorld, so DataDome's script in the page handles it as it does for the site), results come back as `SCRPC_RESULT:<id>:<status>:<body>` console messages (all other console output of the page is dropped). A DataDome 403 inside the page waits up to 6 s for a fresh `datadome` cookie (invisible challenge) and otherwise shows the page in a window for a captcha; a new cookie retries the queued requests, closing the window fails them. The page and Chromium close after 2 min without such requests. Never imitate a browser from Qt's HTTP stack (headers, cookies, TLS) to get past DataDome; let the real browser page do the request. The sign-in window and this page share one `QWebEngineProfile` (`src/api/WebProfile`, acquire/release with a refcount, destroyed by `Application` at exit after the pages): two profile instances on the same storage directory fail on Chromium's `LOCK` files.
- **Sign-in** (`src/api/AuthManager`): the only QtWebEngine use. The shared profile (`webprofile::acquire`) named `soundcloud_profile` with the persistent storage `~/.config/soundcloud_rpc/storage` (the same profile the old web-wrapper client used, so an existing login is picked up silently) loads its cookies; when an `oauth_token` cookie for soundcloud.com appears, it becomes the token (saved to `~/.config/soundcloud_rpc/token`, mode 0600) and the profile is released (page before profile). Only if no cookie arrives within 4 s (a cold Chromium start is slow) does the sign-in window (soundcloud.com/signin) show. The User-Agent has its `QtWebEngine/x.y` token stripped and a stealth script is injected at DocumentCreation (webdriver, `window.chrome`, plugins, languages), because Cloudflare/DataDome guard the sign-in page; don't remove these casually. A token the API rejected is remembered so the same stale cookie is not accepted again; *Sign Out* deletes the token and the profile's cookies.
- **Discord** (`src/integrations/DiscordIpc`, `DiscordPresence`): own IPC client on `QLocalSocket` (frames: little-endian opcode + length + JSON; handshake `{v:1, client_id}`, then `SET_ACTIVITY` with pid and nonce; ping/pong). Socket candidates: `$XDG_RUNTIME_DIR`, `$TMPDIR`, `/tmp`, then the Flatpak/Snap subdirectories (`app/com.discordapp.Discord`, `app/dev.vencord.Vesktop`, `snap.discord`), `discord-ipc-0..9`. It converges to the latest desired activity: dedupes (`DiscordActivity::same`, timestamps tolerate 1.5 s), waits 0.25 s after the last real change so transient states collapse, rate limits with a sliding window of 4 updates per 20 s (Discord allows ~5; throttled updates are delayed, never dropped), reconnects every 5 s and re-sends after reconnect; an `ERROR` response (payload rejected) does not tear down the connection. `DiscordPresence::cleanText` enforces Discord's 2..128 byte limit on details/state (violations used to cause reconnect loops). Sync with the music (the old web client was second-accurate and this must stay so): timestamps are unix milliseconds computed from `PlayerController::precisePosition()` (the last position report extrapolated while audio runs, so it doesn't lag the backend's report steps); a playing activity is only published while `audible()` (PlayingState and the position advanced within the last 1.2 s; not mediaStatus, which after a seek does not reliably return to BufferedMedia and froze the timestamps), so a skip or a re-resolve doesn't start Discord's clock before the sound; `DiscordActivity::same` tolerates 1.5 s, and a 1 s refresh re-derives the timestamps, so stalls, seeks and skips are corrected within a second while steady playback sends nothing; for 1 s after a seek, position reports more than 2 s away from the target are ignored (the backend can still report the old position). The large image is `PlayerController::artworkUrl()`: the cover the UI actually loaded (`displayedArtwork`, bound from `NowPlayingPanel`), so a 404 artwork falls back to the avatar there too (also for MPRIS `mpris:artUrl`). The client id `1289606421368799345` owns the asset keys `bw-exploring-bordered-white` / `bw-icon-bordered-white`.
- **MPRIS** (`src/integrations/Mpris`): `org.mpris.MediaPlayer2.soundcloud_rpc` at `/org/mpris/MediaPlayer2`, root and Player adaptors (Seek/SetPosition, `Seeked`, writable Volume/Shuffle/LoopStatus, OpenUri for soundcloud.com links). `PropertiesChanged` is emitted by hand (`QDBusMessage`), status bars refresh only on it; the invalidated list must be a `QStringList` (signature `as`).
- **UI** (`qml/`, module `SoundCloudRpc`; files are served from the module root via `QT_RESOURCE_ALIAS` so the implicit directory import sees the `Style` singleton): `Main.qml` = `Rail` (sections, and the settings gear above the avatar) | a `StackLayout` of one `StackView` per section (Home, Feed, Library, Search, Settings; pages pushed with `openItem`; anything in the UI navigates through `App.openItem` / `App.playCollection` / `App.showMenu`, signals handled in `Main.qml`, because `ApplicationWindow.window` is null inside handlers like `TapHandler`) | `NowPlayingPanel` (cover → idle screen, waveform `Waveform`, transport, like/queue/idle/volume). `SettingsPage` (also tray *Settings…*, `Ctrl+,`; reachable while signed out): color mode, idle screen (automatic + delay, theme, preview) and language; the language (`App.language`, QSettings `ui/language`: `system` / `en` / `ru`) is only stored, nothing is translated yet. The rail's glyph (also on the sign-in panel) is `Style.logo`: `logo.png` (white) or `logo-dark.png` (the same glyph in #111111), picked by `App.logoStyle` (`auto` = black when `Style.isLight`, or `white` / `black`; QSettings `ui/logo`). The rail has `z: 2`: StackView push/pop slides pages out of the section's bounds, and they must pass under the rail. `Waveform` colors each bar by the fraction of it already played (the bar under the edge blends outline into accent) instead of clipping a played copy: a clip only moves in whole pixels, which on the ~310 px bar was one visible step a second. Shared pieces: `Chip` / `ChipBar`, `ItemRow` / `ItemList`, `Card` / `ItemGrid` / `Shelf`, `ItemMenu` (right-click), `PageHeader` (back button when the page's stack is deeper than 1; its `page` property must not be bound to an id named `page`, pages use `id: root`), `Icon` (SVG paths on a 24-grid drawn with `Shape`/CurveRenderer, no icon font), `ArtImage` (rounded artwork drawn as a `Shape` filled with the image's texture via `ShapePath.fillItem`; the texture sits in its native pixels at the shape's origin, so `fillTransform` scales and centers it like PreserveAspectCrop. Don't go back to a `MultiEffect` mask: the mask is a layer of an invisible item and came back empty (black squares) after the tab holding it was hidden and shown again. sndcdn.com doesn't render every size of every image and some artwork URLs 404 outright, so `ArtImage` tries `-t500x500`/`-large`, then `fallback` (the uploader's avatar, `artworkFallback` on items), and remembers dead URLs in `Style.missingArt`. Only a 4xx answer makes a URL dead at once (`App.isGone`, recorded by the QML engine's own `QNetworkAccessManager`, `src/app/QmlNetwork`); other errors, such as the CDN closing its HTTP/2 connection mid-load (`QQuickImage: Connection closed`), are retried twice after 1.5 s / 5 s first, because they used to blank covers until a restart). Playlists without artwork of their own show their first track's cover, like the site: outside their own page their tracks are id-only stubs, so `SoundCloudApi::resolveArtwork` batch-fetches those first tracks (`artworkPending` / `artworkTrackId` on the item) for list pages and Home shelves. Colors follow the system Qt palette (`Style.qml` reads `SystemPalette`; on this machine qt6ct with the scheme Noctalia writes to `~/.config/qt6ct/colors/noctalia.conf`, so the app matches the desktop and follows Noctalia's theme): `bg`, `ink` and `accent` are the palette's window, window text and accent; `panel`/`surface`/`raised`/`hover`/`outline` and `inkDim`/`inkFaint` are mixes of those, so dark and light schemes both work; `onAccent` picks whichever of the window color and highlighted text contrasts more with the accent. The accent marks active things (play buttons, active chip, played waveform, rail indicator, liked/shuffle/repeat, volume, now-playing bars). Never hard-code colors in the main UI; the idle themes are the exception and keep their own grayscale look on purpose. qt6ct reads its scheme only at startup, so `ThemeWatcher` (`src/app`) watches `qt6ct.conf` and the scheme file it names (and their directories, since theme switchers replace files by rename), parses the scheme (`active_colors`/`inactive_colors`/`disabled_colors`, colors in `QPalette::ColorRole` order) and sets it as the application palette; `SystemPalette` follows, so a theme switch in Noctalia recolors the running app. Only active when `QT_QPA_PLATFORMTHEME` is qt6ct and `custom_palette=true`. The qt6ct plugin loads into the app only because the user's system and this flake use the same qtbase; a mismatched Qt would refuse it and the app would fall back to Qt's default (light) palette. A QML property named `on<Upper>...` is parsed as a signal handler (that broke `Style` once). Tabs inside pages create their list lazily on first show (`StackLayout.onIsCurrentItemChanged`; a binding with `onActiveChanged` looped).
- **Window size**: the client window is always a floating 1431x500 banner (Hyprland rule in the user's config), so every screen is designed for that size first (horizontal compositions: info column left, list right); smaller sizes only need to degrade gracefully. The Wayland app_id is `soundcloud-rpc` (`setDesktopFileName`), which the rule matches; the sign-in window shares it.
- **Idle screen** (`qml/idle/`, static QML module `SoundCloudRpc.Idle`, shared with `soundcloud-rpc-preview`): opened by clicking the cover, the screen button, `Ctrl+I`, the tray's *Idle Screen* → *Show Idle Screen*, the settings' *Preview*, or by itself: `Application` restarts a single-shot timer on input to the window (event filter: press, double click, wheel, key, touch, pointer moved ≥ 4 px since the last input) and opens it when the timer fires while music plays and the window is visible and not minimized (QSettings `idle/auto`, default on; `idle/delay`, 5..60 s, default 30). Playback starting and the window being shown restart the timer, so a refused timeout just waits; a screen opened by the timer closes again when the music stops, one opened by hand does not. `IdleScreen.qml` loads `themes/<Theme>.qml` by URL and gets `title/artist/cover/syncPosition/duration/playing` and the audio values from `Main.qml` bindings; it extrapolates a smooth `position` between the player's reports. A click or key press over it closes it (ignored for 400 ms after opening); moving the pointer does not; hiding the window closes it. `Application::setIdleActive` also toggles the analyser, so nothing is analysed while it is closed. Music reactivity: `AudioAnalyser` taps the decoded PCM with `QAudioBufferOutput` (Qt ≥ 6.8, FFmpeg backend, set on the same `QMediaPlayer` next to the audio output) and emulates WebAudio's `AnalyserNode.getByteFrequencyData` (fftSize 1024, Blackman window, smoothing 0.5, -90..-8 dB) so the themes' calibration from the old in-page analyser still fits: bass/mid/treble/level (0..1, ~30/s) and 32-band log-spaced spectra (40 Hz..16 kHz) of the mix and of each channel; `bandsChanged` is emitted before `levelsChanged` because a theme reacts when the level changes. `ThemeBase` normalises them against an adaptive floor/ceiling, smooths them into `bass/mid/treble/level` and `bands`/`bandsL`/`bandsR` (left and right share one scale), decays everything to 0 when updates stop, and emits `beatDetected()` / a decaying `beat`; themes should react with light only (brightness, halos, particle rate), never by moving covers or text. The selected theme lives in QSettings (`idle/theme`, org `SoundCloud`, app `soundcloud-rpc`) and the tray menu. Themes are grayscale with the cover as the only color; every theme derives from `themes/ThemeBase.qml` and is designed for a 286x100 "stage" (`u` = 1% of its height) that scales to fit, with full-bleed backdrops in `background`; shared parts are `TrackInfo`, `Cover`, `Progress`, `Grain`, `Vignette`, `BlurBackdrop`, `Shadow`. Never move covers or text with sub-pixel animation (1-2 px jitter); the stage is centered on whole pixels. Rendering: the window is multisampled with 8 bits per color channel (`Application` sets 4 samples and R/G/B 8 on the window's format before it is first shown and warns when the surface it got has less; the preview sets the same default format). The color sizes must be explicit: with samples set and no sizes, NVIDIA's EGL picks an RGB565 config, which showed as green-tinted dark grays ((13,13,13) became (8,12,8)) and dot-pattern dithering on dark gradients. A green tint where R and B are equal and G is a few steps higher is that, not the content or the wallpaper. Pulsing/tilted/swinging covers are pre-rendered once into a 2x `layer` (`layer.smooth`, `layer.mipmap`, `layer.textureSize` 2x, shadow kept outside the layer) and only that texture is transformed (see `Aurora`, `BlurCover`, `Polaroid`); `Cover`'s mask layer has its own 2x size and `layer.samples`. QML gotchas found the hard way: turning the `ParticleSystem` item into a `layer` squashed the particle field vertically, so `Particles` blooms a `ShaderEffectSource` snapshot through a `MultiEffect` with explicit x/y/width/height; a Repeater delegate `Item` cannot declare a property named `left`; `MultiEffect` masks only work with an `Item` wrapping the mask `Rectangle` (`layer.enabled`, `visible: false`); the blur radius is in pixels of the item the effect is applied to, so wide blurs need a small item scaled up (see `BlurBackdrop`); masks inside rotating parents render wrongly; `offscreen` rendering is the software scene graph and draws neither `MultiEffect` nor `ShapePath.fillItem` (artwork stays empty); for GPU output without showing anything, `QQuickWindow::grabWindow()` on a window that was `create()`d but never shown renders offscreen through the real RHI. Check themes at the real size with `./build/soundcloud-rpc-preview --fixed --size 1431x500` (add `--shots DIR --only Theme,Theme --cover FILE` to save PNGs, `--music` for a fake stereo music signal, `--fps` to print the frame rate).
- **Layout screenshots**: `SOUNDCLOUD_RPC_SCREENSHOT=out.png` (optional `SOUNDCLOUD_RPC_SCREENSHOT_DELAY=ms`) shows the window, saves it after a few seconds and quits; with `QT_QPA_PLATFORM=offscreen` and a separate `HOME`/`XDG_RUNTIME_DIR` it runs without touching the user's session (it only shows the sign-in state without a token).
- Settings: QSettings at `~/.config/SoundCloud/soundcloud-rpc.conf`; sign-in profile and token in `~/.config/soundcloud_rpc/`.
